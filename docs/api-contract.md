# API Contract

## Confirmed Conventions

- Base path: `/api/v1`
- Transport: REST over HTTP
- Documentation: Swagger/OpenAPI generated by the backend
- Request validation: DTO/schema-based validation at backend boundaries
- Error handling: consistent HTTP status codes and explicit validation errors

## Current Implemented Endpoint

```http
GET /api/v1/health
```

Returns service status metadata only. It does not expose product state.

## Future Contract Process

Product endpoints should be added only after requirements are agreed. Before implementation, document:

- Resource name and route
- Request parameters/body
- Response shape
- Authentication and authorization requirements
- Validation rules
- Failure cases and status codes
- Frontend behavior for loading, empty, and error states

## Future Candidate Resources

These are not confirmed implementation commitments:

- Properties
- Availability
- Bookings or booking requests
- Enquiries
- Authentication
- Reviews
- Admin or host-management workflows
